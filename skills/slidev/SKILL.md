# Slidev - Presentation Slides for Developers

Web-based slides maker built on Vite, Vue, and Markdown.

## When to Use

- Technical presentations or slidedecks with live code examples
- Syntax-highlighted code snippets with animations
- Interactive demos (Monaco editor, runnable code)
- Mathematical equations (LaTeX) or diagrams (Mermaid, PlantUML)
- Record presentations with presenter notes
- Export to PDF, PPTX, or host as SPA
- Code walkthroughs for developer talks or workshops

## Package manager and disk usage

Prefer PNPM for new Slidev projects and templates that do not already mandate a package manager. Its shared content-addressable store reuses package contents across projects through links or filesystem clones where supported, reducing duplicate dependency storage. Projects still have a local `node_modules` layout, and build outputs, caches and browser downloads can consume additional space.

- Check the project's `packageManager` field, lockfile and repository instructions before installing. Respect an existing package-manager convention; do not migrate it or create a competing lockfile without approval.
- Use `pnpm install`, `pnpm add` and `pnpm run` for PNPM projects. Use `pnpm exec` for installed tools rather than `npx` or repeated one-off downloads. Use `pnpm install --frozen-lockfile` when reproducing an existing lockfile without dependency changes.
- Reuse the shared PNPM store. Do not copy a template's `node_modules` directory or configure a separate store per presentation by default. Keep `pnpm-lock.yaml` with the project.
- If PNPM is unavailable, report the prerequisite and ask before switching package managers. Do not silently fall back to `npm install`. Disk-space concerns do not authorize deleting other projects, pruning shared stores or clearing browser caches.

## Quick Start

```bash
pnpm create slidev    # Create project
pnpm run dev          # Start dev server (opens http://localhost:3030)
pnpm run build        # Build static SPA
pnpm run export       # Export to PDF (requires playwright-chromium)
```

**Verify**: After `pnpm run dev`, confirm slides load at `http://localhost:3030`. After `pnpm run export`, check the output PDF exists in the project root.

## Layout review before delivery

A successful build or export does not establish that the slides look correct. Inspect every slide visually in the browser and in each requested output format, including intermediate click states when exported.

- Reserve separate areas for headings, body content, decorative images, logos and footers. Check text against the visible artwork, not just its image rectangle: transparent padding can hide collisions.
- Check the longest title, subtitle and bullet text for extra wrapping. Keep text clear of other text, rules and visual elements, with consistent margins and enough space above footers and legal blocks.
- Review alignment, bullet indentation, line spacing and content balance across the deck. Check both edges of each column and the bottom of each text box for clipping or overflow.
- Wait for fonts and assets to load before capturing screenshots. Inspect screenshots at presentation size; DOM snapshots and text extraction alone cannot reveal overlapping or clipped elements.
- Fix layout problems by shortening copy, splitting a slide or adjusting the available text area first. Preserve readable type sizes and the template's visual hierarchy rather than shrinking the entire slide to hide overflow.
- Before exporting PDF or PPTX, read and follow the [export review](references/core-exporting.md#review-exported-layout), including spacing and editable-text checks where applicable. Recheck the exported file after every correction and disclose any output format you could not visually inspect.
- Track review coverage by slide and output format, including exported click states. After corrections, recheck affected slides, then visually review the complete final deck before declaring it validated. Report partial coverage explicitly.

## Basic Syntax

```md
---
theme: default
title: My Presentation
---

# First Slide

Content here

---

# Second Slide

More content

<!--
Presenter notes go here
-->
```

- `---` separates slides
- First frontmatter = headmatter (deck config)
- HTML comments = presenter notes
